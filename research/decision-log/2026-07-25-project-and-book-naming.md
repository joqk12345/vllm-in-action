# 项目与书籍命名决策

## 决定

```text
Repository: vllm-in-action
中文书名: 《vLLM 工程实践》
中文副标题: 从推理原理到生产级服务
English working title: vLLM in Action
English subtitle: From Inference Mechanics to Production Serving
```

仓库名与最终书名分开承担职责：

- `vllm-in-action` 是稳定、简短、容易发现的工程仓库标识。
- 《vLLM 工程实践》描述本书的知识类型和方法。
- “从推理原理到生产级服务”明确内容起点、终点和读者收益。

## 背景

项目最初使用：

```text
vLLM in Action / vLLM 实战
从性能模型到生产推理平台
```

随着知识库形成，实际内容已经超出一般“上手实战”：

- 版本与来源追踪；
- 推理机制和请求生命周期；
- workload、SLO 与性能指标；
- 可复现 benchmark；
- 配置收益、代价和失效边界；
- 生产可观测性、可靠性、安全和升级；
- 对实验性能力的证据分级与回退设计。

因此需要在第一次 Git commit 前重新评估命名是否准确表达这套方法。

## 评估标准

1. **读者定位：** 是否面向推理工程师和生产平台建设者。
2. **内容覆盖：** 是否同时容纳原理、实验、部署与运维。
3. **长期有效：** 是否能承受 vLLM API、默认值和架构持续演进。
4. **可发现性：** 是否简短、容易记忆和搜索。
5. **边界诚实：** 是否避免承诺覆盖完整基础设施平台或永恒“最佳配置”。
6. **官方区分：** 是否不会让项目看起来像 vLLM 官方文档或官方发行物。

## 候选方案

### `vllm-in-action`

优点：

- 简短、易记，适合仓库和英文工作名；
- 能容纳教程、实验、源码研究和生产案例；
- 不把内容限定在某一种部署拓扑。

限制：

- “In Action/实战”容易让读者预期快速教程或配置配方；
- 不能单独表达本书的证据纪律和工程深度；
- 出版前仍需做正式名称与权利检索。

结论：保留为仓库名和英文工作名，但不直接作为中文主书名。

### 《vLLM 实战》

优点：

- 通俗直接；
- 对初次接触 vLLM 的读者友好。

限制：

- 容易被理解为命令、参数和案例集合；
- 不能准确表达性能方法、证据台账和生产生命周期；
- 容易诱导“给出一个最优参数”的错误期待。

结论：不再作为中文主书名。

### 《vLLM 工程实践》

优点：

- 能同时容纳原理、测量、决策与生产运维；
- “实践”允许给出建议，“工程”要求写明约束、证据、代价与回退；
- 与本项目“先验证，再总结”的规则一致。

限制：

- 比“实战”略严肃；
- 需要副标题进一步说明范围。

结论：采用。

### `vllm-production-playbook`

优点：生产定位鲜明，适合 runbook 和检查清单。
限制：弱化推理原理、源码研究和性能模型。
结论：不采用，可作为第 16 章的概念。

### `vllm-engineering-handbook`

优点：很适合持续更新的参考型知识库。
限制：更像条目式手册，不符合当前循序渐进的成书结构。
结论：不采用。

### `vllm-best-practices`

优点：搜索意图直接。
限制：“最佳”会随版本、模型、硬件和 workload 变化，与本项目反对无条件结论的原则冲突。
结论：明确不采用。

## 副标题取舍

原副标题“从性能模型到生产推理平台”存在两个问题：

- “性能模型”对目标读者不够直观；
- “生产推理平台”可能暗示完整覆盖 Kubernetes、控制面、模型治理和全部平台基础设施。

采用“从推理原理到生产级服务”：

- “推理原理”覆盖请求生命周期、调度、KV Cache、并行和 Frontend；
- “生产级服务”覆盖 API、SLO、benchmark、可观测性、可靠性、安全和升级；
- 明确这是关于构建和运营服务，而不是承诺提供一个完整平台产品。

## 被明确拒绝的品牌承诺

本书不承诺：

- 提供跨版本永远有效的“最佳参数”；
- 覆盖所有模型、硬件和部署平台；
- 代表 vLLM 官方立场；
- 仅凭上游功能存在就推荐用于生产；
- 把一次 benchmark 结果外推到所有工作负载。

本书承诺：

> 对每项工程建议说明适用版本、工作负载、目标指标、证据、代价、失效边界与回退方式。

## 重新评估条件

出现以下任一情况时重新评估名称：

1. 正式出版前发现显著同名出版物、项目或权利冲突；
2. 全书范围收缩为纯生产 runbook；
3. 全书范围扩展到多个推理引擎，不再以 vLLM 为主；
4. 获得 vLLM 官方合作或品牌使用要求；
5. 目标读者从工程师转向完全入门读者。
